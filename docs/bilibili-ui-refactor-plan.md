# Bilibili 播放器与插件设置 UI 重构计划

日期：2026-09-14；实施更新：2026-09-15。UI 代码候选已交付 0.2.11，等待用户统一验收。全部视觉取样与像素级对照尚未完成。下方为原规划，最新实施结果见第 9 节。

本文件是本次 UI 专项的权威计划。它细化并取代 `player-ui-and-ai-continuity-plan.md` 第 1 节的 UI 草案；该文档中的 AI 连续运行、高能进度条仍是独立待办。本轮用户要求先洞察、规划，不把这些功能混入 UI 重构。

## 1. 目标与完成定义

让已有功能使用 B 站播放器的布局、图标语言、菜单层级、参数控件和交互习惯。相似功能按同一参考版本逐项复刻，而不是只套黑底蓝色主题。插件独有功能复用同一套控件与排版，明确属于扩展设计。

“1:1”按三层验收：

- 视觉：相同参考条件下核对按钮顺序、图标轮廓、字号字重、颜色透明度、间距、圆角、滑杆、分隔线、面板锚点和选中/悬停状态。
- 行为：分别核对悬停、单击、再次单击、移入面板、离开、选择、外部点击、Esc、Tab、方向键、拖动和失焦；打开菜单不能顺带切换播放参数。
- 内容：仅包含已经实现且在当前模式可用的功能；不放占位按钮，不因参考页有某功能就新增后端能力。

标准宽度采用逐项复刻；320/480 像素小窗必须做必要的布局适配，保留顺序和操作语义。小窗适配与插件独有页面单列验收，不能声称它们在 B 站有完全一致的原版。

- 设置初层为深色紧凑浮层：镜像画面、单集循环、自动开播、更多播放设置。
- “更多播放设置”在视频区域内展示深色分组面板：播放方式、视频比例、播放策略、音量均衡、其他设置。选项为紧凑矩形，选中蓝底，其他设置使用小复选框；不能把所有参数都设计为同一种胶囊开关。

| 弹幕区域、不透明度、字号、速度 | 弹幕浮层 | 复用当前 config，支持多少档就显示多少档，不引入虚假值 |

| 字幕显示、轨道 | 字幕菜单 | 正常轨道选择在前；无轨道仍能导入/关联，不把入口整体禁用 |
| 字幕历史开关、段数 | 便捷入口 + 字幕设置 | 保留现有快速访问；窄窗允许归入字幕菜单，非逐字稿 |
| 字幕字号、颜色、背景/文本不透明度、偏移 | 字幕设置 | 参考原生字幕面板；原站没有的项目采用同样的行和滑杆 |

| 快捷键、关闭暂停、滚轮音量、浮动入口、小窗模式、恢复默认、失败重试 | 完整设置 | 同一数据源；错误/重试在相关组，正常状态不常驻诊断卡片 |
| 清晰度、编解码、音量均衡、镜像、循环、关灯、智能遮挡/屏蔽 | 不因复刻新增 | 这些参考项未在本轮建立本项目完整支持证据，默认不出按钮；实施前若找到已有完整能力再补矩阵 |

## 5. 信息架构与参数语义

播放器：进度条 + 左侧播放/切集/时间 + 右侧适用控件。B 站已有项保持相对次序，字幕与弹幕等扩展入口经过宽度预算后插入；不在取样完成前臆定所有像素。

设置分为两层：齿轮先打开紧凑快捷面板，呈现已有常用播放选项与“更多设置”；完整设置保留播放、字幕、弹幕、快捷键分类，内容按 B 站“更多播放设置”的分组标题、矩形选择、复选框/开关、滑杆、数值排版组织。移除嵌套装饰卡片和常驻技术说明。设置中的恢复默认继续沿用原有范围，不扩大重置的数据。

扩展工具栏 popup 使用同一套颜色、字号、按钮与选中态，保留小窗入口、设置入口和必要的站点/失败反馈。播放器快捷面板、完整设置和 popup 共用控件，避免三个入口显示不同值。以播放器深色面板为本次默认视觉目标，不再由系统主题意外改变播放器设置外观。

参数映射先于画滑杆：

- 不透明度可将内部 0–1 映射为百分比显示，但不改变持久化格式或既有范围；不将“透明度”方向反转。
- 字幕/弹幕字号不能仅为匹配截图把 px 假标成 %；只有定义明确、可逆的基准后才能使用百分比，否则保留真实单位。
- 显示区域按当前 1/4、1/2、full 映射档位；不复制当前引擎不支持的 3/4 档。
- 弹幕速度必须核对不同引擎的 danSpeed 单位和增减方向，再决定“慢—快”的映射；现设置中的 s 文案不能未经核对继承。
- “长按右键”改为无歧义的“长按 → 倍速”；不改变快捷键定义。
- 显示关闭、AI 功能关闭、当前识别任务停止、字幕来源选择保持不同语义。精简说明不等于删除必要限制和错误解决入口。

## 6. 实现顺序与阶段出口

### A. 补齐参考和能力清单

只读采集普通视频、有原生字幕的视频、当前主要使用的播放布局；直播只验证已有能力差异。取样底栏、倍速、音量、字幕、弹幕、快捷设置、更多设置、tooltip。记录日期、播放区域尺寸、缩放、触发方式、状态与具体尺寸；截图不包含个人资料、推荐列表或私密信息。

出口：每个共通控件有参考，功能矩阵无悬空按钮；未能取得的样本明确标记，不能自行宣布 1:1。

### B. 先做可审阅的交互稿

在隔离预览中用合成视频占位和本地模拟状态制作底栏、菜单、完整设置/popup；不触发 AI、字幕请求或真实持久化。覆盖 800、480、320 宽度及 320×180 低高度，展现正常、选中、加载、失败、空数据、菜单打开状态。

出口：逐项与参考同尺寸并排/叠图检查；菜单不越界，短标签不折行，没有功能因缩窄而失去入口。对照稿完成后才接入真实功能，避免边改业务边猜外观。

### C. 共用视觉和弹层基础

建立限定在 LayerPiP 根元素下的视觉 token，以及图标按钮、提示、菜单项、开关、矩形单选、滑杆、分组行组件。优先复用现有 React/MobX 与 Trigger，无必要不加依赖。整合当前 `layerpip.css`、`modernPlayer.css`、`bilibiliSurfaces.css` 中相关规则，不继续在末尾堆叠覆盖。

播放器建立互斥菜单状态；挂载到所属 Document PiP 文档，处理锚点、边缘避让、低高度滚动、外部点击、Esc 和焦点归还。面板打开/拖动/键盘聚焦时控制栏保持显示；跨窗口关闭清理监听。局部适配旧 Dropdown 调用，避免扩大影响面。

出口：独立预览中的菜单与焦点行为通过，样式不污染 B 站原页面。

### D. 接入播放器与设置

先接基础播放/进度/倍速/音量，再接弹幕、字幕、AI 精简视图，最后接完整设置与 popup。保留原数据源与保存路径，不重写 provider、媒体控制、字幕身份绑定或 AI 状态机。每完成一组核对入口、数值方向、实际状态同步、失败反馈和可达性。

若 UI 简化必须依赖 AI 自动恢复，记录为明确依赖并单独处理，不能仅改文案掩盖 0.2.10 的限制。

### E. 定向验证与交付

先核对差异，再按实际改动选取最小验证集。完成复刻对照和相关检查后，依项目规则递增版本，读取交付标准，通过 staging 构建、校验、保留旧产物再替换固定 `dist`，更新 progress.md。用户自行重新加载并验收实际 Document PiP；构建不等于安装或验收。没有授权的提交、推送或发布不执行。

## 7. 验证与验收门槛

| 具体风险 | 最小验证 |
| --- | --- |
| 点击同时打开菜单与改参数 | 点击/悬停入口、选择、关闭后检查原视频属性和开关值 |
| 焦点导致 Space/方向键失效或输入时误控视频 | 运行项目要求的 `node scripts/keyboard-regression.mjs`；追加仅覆盖新菜单 Esc/Tab/返回焦点的交互检查 |
| 弹层跑到主网页/窄窗裁切/菜单闪退 | 所属文档挂载检查、320/480/800 和低高度截图；用户实机验证 Document PiP |
| 参数滑杆改错单位/方向或两处显示不同 | 对实际 mapper 做端点、档位、往返和跨入口状态检查，不为纯样式写测试 |
| UI 改动破坏保存/CID 选择 | 复用现有提交路径；仅在相关接线改动后验证临时导入、保存关联、失败保持当前视频 |
| 图标尺寸、间距、颜色看似接近但不一致 | 同尺寸的参考/实现截图逐项标注差异；几何关键值以 CSS px 记录，字体抗锯齿不按逐像素强求 |
| CSS 或组件引入生产错误 | 一次相关编译/生产构建；若全仓既有类型错误存在，区分新增诊断 |
| 基础播放/原生模式退化 | 核对媒体后端无非必要修改；用户检查音量、进度、键盘和双模式日常体验 |

通过标准：共通项目全部有对照结论；扩展项目视觉一致；所有已有必要能力仍可到达；无空按钮、无新增不支持功能、无解释卡片常驻遮挡视频；错误可理解且不影响播放。
