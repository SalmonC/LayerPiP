# 0.2.20 审阅与 0.2.22 双画面首版

本轮按用户要求审阅 DeepSeek 的代码、修复问题并分步推进未完成特性。原实施报告保留；当前实现边界以本文件及 AGENT_SYNC.md 为准。

## 已修复的实际代码问题

1. `HeatBarOverlay` 在 `useMemo` 内读曲线开关、依赖却只有曲线和时长。开关变化可能不重算，MobX 订阅还会在重渲染时丢失。改为渲染时读取、显式加入依赖。
2. 高能条 `release()` 只卸监听、不清 video 引用，重开同一 video 时不重新挂监听；还漏读最后 played 快照。现已对称释放、重绑并结算。
3. 同 cid 换源后 suspended 永不解除；存储读取、曲线请求可能越过切视频与卸载。增加代次闸门、metadata 后重新确认身份；路由先到、媒体资源后到时暂停采样，避免旧 played 归到新 cid。
4. 各内容脚本的 storage 读—并—写不是原子操作，旧注释“不会丢区间”错误。改由后台队列串行处理所有合并与共享淘汰索引；保留原存储键/结构，不迁移生产数据。删除未使用的 clearWatched 方法，避免留下绕过单写入者的删除入口。
5. `fetchPbpCurve` 把任意非法响应判为正常无曲线。现只把明确 err_id=3（兼容 debug JSON 字符串）判为无数据；异常维持 error，播放时退避重试。限制输入点数和推导数组长度，避免异常 step 分配超大数组。
6. 官方 IndexedDB 打开请求提前结束后，迟到的成功连接可能不关闭，现已补关闭；仍只读官方数据，不创建数据库。
7. Dropdown 可用高度原来没有扣播放器顶部坐标，双画面内偏移会越界；改为播放器内相对高度。
8. 交接关于“patch 机制未生效”与实际不符：workspace 和锁文件一直有 rc-util 补丁。新增 webext-bridge 补丁在断连回调内同步读取 runtime.lastError，保留既有重连流程；非 BFCache 异常仍输出警告。未在用户 Edge 重现 BFCache，不能宣称错误列表已清空。
9. ja/ko/fr/es 高能条文案完成翻译。

## 双画面首版的选择

采用“现有主播放器 + 一个视频页 iframe”。主视频不重新创建，字幕、弹幕和播放进度保留；新增画面用 B 站自己的播放器与控制栏。这是报告中两种所有权方案之一，避免同时保留原主视频又新建其副本。

入口：B 站普通视频的增强小窗 → 播放设置 → 多画面。第二路支持完整 HTTPS www.bilibili.com/video 链接或 BV 号；支持分 P。短链、直播、番剧及非 B 站地址不在首版范围内。

- 同一个 PiP 窗口，最多两路；宽窗左右排列，600px 以下上下排列。
- 初始全静音，开启某路声音先静音另一路；监听原生音量变化维持单路有声。焦点切换不暂停另一视频。
- 保留 iframe 的原生控制键；宿主与子文档按键不重复处理。扩展全局播放/快进/后退操作指向最后点击/聚焦的画面，标题以“控制中”明确标识。系统媒体会话仍由主路持有，子路禁止注册；此首版不宣称系统媒体键全部跟随子路。
- iframe.name 仅用来提前关闭扩展注入入口；宿主根据自己创建的 frame 对象、同源检查及目标视频 URL 直接操作 DOM，不接收不可信 postMessage 指令，因此无需额外消息握手。限制在所属帧，不能凭 name 请求宿主操作。
- 子画面禁止再次开小窗，隐藏不可用的全屏/宽屏/PiP 按钮；整个视频页用限定于子文档的 CSS 收敛到原生播放器区域。未增加扩展权限。
- 子路被拒绝自动播放时提示在画面内点击；加载失败、超时或跳离目标视频时销毁子帧，主路保留。
- 主页面切视频时退出多画面，让现有单路生命周期完成切换。退出保留主路当前进度，恢复进入前静音状态；关闭窗口释放子媒体、帧和监听。
- 不写 B 站数据库或网页存储。控制媒体音量会触发站点自身的事件处理，其偏好行为仍需实机观察。

## 验证和边界

- TypeScript 与 0.2.20 比较，归一化补丁导致的 node_modules 路径变化后仍为既有 92 项，无新增错误；并非全仓类型检查通过。
- 运行项目指定 keyboard-regression：输入框/按钮保护、跨窗口绑定、失焦释放、重复绑定均通过。
- 本地隔离夹具验证主节点保留/还原、第二帧释放、独奏切换、命令目标、非法链接拒绝和重开。未连接用户 Edge，也没有对真实 B 站页面做视觉验收。
- 采集器夹具验证同视频重开监听、尾段结算、同 cid 换源、迟到读取隔离和路由先到媒体后到。夹具存储完全隔离，未读写生产观看记录。
- 代码审阅和构建不能保证真实站点布局、自动播放策略与长时间播放效果；这些留给用户统一验收。

后续阶段：四路、拖拽分隔、布局记忆、子路接入插件字幕/弹幕、共享 AI 资源调度；当前没有为这些未实现能力展示按钮。
