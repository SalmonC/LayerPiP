## 提前识别实施约束

公开普通点播样本的官方 playurl 接口已返回 AAC 独立音轨、初始化范围与 SIDX 索引；短范围请求返回 206、精确响应长度及允许跨域读取。该 CDN 未暴露 Content-Range 响应头，页面端不能强制读取该头；应要求 206 并有界读取、核对字节数，拒绝服务器忽略 Range 返回的整轨 200。不能承诺复用播放器缓存或没有额外下载流量。

采用固定版本 MP4Box.js 2.4.1 解封装，BSD-3-Clause 许可随包保留。初始化和单个片段均限制大小；聚合约 6–8 秒音频后执行一次推理，达到约 30 秒提前量后等待。用样本媒体时间生成 PCM 时间轴，不能用下载耗时或完成时刻代替字幕时间。失败进入可手动重试状态，不改变视频进度或暂停主视频。暂停、跳转、关闭、换源和关闭 AI 的释放行为必须验证。

已完成的前置核验：隔离 Chromium 支持 AAC AudioDecoder；公开样本的 96 秒中段经 MP4Box 提取 94 个样本，首样本 CTS / timescale 为 96 秒。样本使用相对 moof 的数据偏移，若采用初始化段加片段的连续输入，必须拒绝依赖原始文件绝对偏移的容器。以上仅证明样本请求和解封装，不代表完整预取字幕已通过验收。

依据：[MP4Box.js 官方接口](https://github.com/gpac/mp4box.js)、[WebCodecs AudioDecoder](https://www.w3.org/TR/webcodecs/#audio-decoder-interface)。

状态：2026-09-11 最小实现和隔离浏览器冒烟完成，待用户实机验收。本文是本功能的权威设计；打包状态记录在 progress.md。

## 目标和取舍

用户只安装 LayerPiP，在插件设置中启用并手动开始识别。首版随包携带多语言 Whisper Base q8 模型及执行引擎，不要求 Python、外部程序、账号或 API Key。先验证真实音频能产生可用字幕，不实现模型商店、下载/卸载、多模型选择、云服务或翻译。语音识别输出原语言；不能把语音识别等同于中英翻译。

AI 总开关默认关闭。关闭时普通播放器菜单隐藏入口，且不加载模型、创建音频上下文或推理 Worker。开启总开关只显示入口；用户点击开始才初始化。关闭总开关立即终止识别并释放资源。原生小窗用户可从原网页的插件设置操作；两种小窗复用相同字幕时间轴。

轻量模型精度、中文标点和延迟需实际验收，不能承诺所有电脑实时运行。首版仅支持正常 1 倍速播放；不支持的音频采集、模型故障或持续落后只停止 AI 并显示可重试状态，不暂停视频、改音量、改播放时间或切换来源。字幕晚到仍按音频时间归位，允许在历史字幕中回看。

## 组件边界

1. `ModelStore` 负责返回固定模型描述与本地资源地址。首版 `BundledModelStore` 只读；未来下载模型可以替换此实现，下载能力需显式声明，不提供虚假的卸载按钮。
2. `TranscriptionEngine` 接受 16 kHz 单声道 PCM、语言提示与音频区间，返回相对时间字幕段。首版 Transformers.js 3.8.1 + WASM 单线程，独立 Worker；未来可替换 WebGPU 或外部模型，不让播放器依赖具体模型库。
3. `AudioCapture` 只从视频 `captureStream()` 获取副本并转换 PCM。不得使用会接管网页音轨的 `createMediaElementSource()`，不得为采集改变源视频属性。采集失败必须退出并解释原因。
4. `AiSubtitleController` 管理开始/停止、资源、状态、分块与代次。一个推理任务加至多一个等待块；有界内存和推理超时。切视频、关小窗、禁用、换字幕源、非 1 倍速或异常应取消旧代次；过期结果不得写入当前轨道。跳转清掉未完成片段并停止，用户可重新开始。
5. `SubtitleManager` 提供显式生成轨道更新接口：不重复增加菜单项，不进入在线翻译流程，转义识别文本，复用快照/历史/全局偏移。停止后可保留已生成字幕，切来源时不能被旧任务抢回。
6. `AiSubtitleControls` 统一呈现模型准备/识别/停止/失败及手动重试。设置总开关和字幕菜单共用控制器，不各自创建模型。

扩展来源的隐藏 `ai-frame.html` 承载 Worker，页面用一次性 MessageChannel 传输 PCM；消息校验来源、长度和类型。推理 JS/WASM 全部打包在扩展内，模型只从固定本地路径加载，禁止运行时远程模型和代码回退。避免将推理放在易被挂起的后台 service worker。

## 首版数据与生命周期

- 分块约 6–8 秒，静音跳过；首版可以不做重叠以避免重复句，边界精度作为已知限制，接口保留片段时间戳。
- 从视频媒体时间标记音频，不采用识别完成的墙钟时间；过滤无效/空白段并限制起止范围。
- 停止/禁用立即移除采集节点、关闭 AudioContext、终止 Worker 和移除 iframe；只操作自己创建的流/轨道。
- 切换字幕来源时停止生成，已有内容由既有字幕逻辑显示或清空。网络字幕、官方字幕和文件字幕不依赖 AI 可用性。
- 不保存音频，不上传识别文本，不自动调用既有 Google 翻译。模型资源清单固定版本与 SHA-256；首次构建下载资源，最终 dist 内自包含。

## 实现分工与检查

主 agent 负责本设计、依赖和模型资源、manifest/构建、代码审核及唯一正式 dist 交付。用户指定的 gpt-5.6-luna / max 子 agent 负责 `src/core/AiSubtitle/`、`src/ai/`、控制组件和必要的配置/播放器/字幕管理器接入，不修改打包脚本、manifest、package、正式产物或既有无关工作。

0.2.9 的实际执行：已按要求创建指定模型与强度的子 agent，但其因额度限制终止，未产出代码。按照用户允许调整策略的授权，由主 agent 完成最小实现及审核。未将这次结果描述成子 agent 编码或独立双人审查。本轮按最新要求重新分配 Luna / max 子 agent 编码，主 agent 审核。

接口映射：`types.ts` 定义 `ModelStore` 和 `TranscriptionEngine`；`LocalEngine.ts` 管理 iframe RPC；`AudioCapture.ts` 采集；`controller.ts` 绑定当前 Provider 和任务代次；`src/ai/frame.ts` / `worker.ts` 执行本地 ASR。首版使用 ScriptProcessor 的短 PCM 回调，昂贵推理在 Worker；迁移 AudioWorklet 是后续音频采集层优化，不改字幕和引擎接口。

隔离验证：8 秒公开英文音频直接识别约 2.4 秒；实际 video.captureStream → iframe → Worker → SubtitleManager 链路得到有效字幕和历史快照，禁用/取消后 iframe 清零、视频仍前进，过期写入句柄被拒绝，无外部网络请求，即使字幕翻译模式已设置也未调用翻译。测试使用独立浏览器临时上下文及本地音频，不操作已安装扩展或用户视频。此结果不构成中文准确率、所有设备性能或 B 站实机验收。

已知首版限制：约 8 秒非重叠分段会截断跨段句子，模型可能误识别，静音门限可能跳过很轻的语音；没有离线完整视频预转录。识别完成时原音频可能已播放结束，因此建议开启历史字幕；关闭历史显示时，已过期片段不会当作当前字幕强行延长。保留源时间戳用于回看，不延迟原视频。

检查针对三个真实风险：旧结果污染新来源/停止后仍采集；真实模型资源或浏览器执行路径不可用；产物缺资源或改变身份。运行一个定向生命周期检查及一个隔离的真实推理冒烟，最后按固定交付脚本构建并回读版本、ID、模型文件及回滚。用户自己重新加载并验收 B 站实际字幕体验；不能把构建成功写成已经实机验收。

## 2026-09-11 用户反馈后的提前识别方案（历史提案）

以下保留当时推导，实施状态和当前限制以上文 2026-09-12 记录为准。其中 30–60 秒窗口、Worker 解码、拖动自动调度与性能指标仍非本次完整实现，不作为已交付承诺。

用户实测字幕明显落后。现有 captureStream 只能捕获正在播放的音频；当前约 8 秒收集窗口再加推理时间，是结构性延迟。增加一个负时间偏移不能生成尚未识别的文本。本节是下一阶段设计，不能当作已经实现或已通过 B 站验证。

可行流程为：当前视频身份 → 获取可访问的独立音轨描述 → 按时间范围预取压缩片段 → 解复用并保留原始时间戳 → Worker 内解码为 16 kHz PCM → 已有本地模型 → 提前填充现有字幕时间轴。这样不必等到原视频播放该片段。

- **首选 B 站普通点播适配**：验证当前播放信息是否提供可访问的 DASH 音轨和分段/字节索引，以 Range 请求取所需后续片段；优先请求音频而非整段视频。CDN 可能命中浏览器缓存，但不能承诺无重复下载。直播、不支持的编码或不可访问音轨继续走现有实时采集，并明确显示当前模式。
- **不直接读取浏览器已缓冲的字节**：`video.buffered` / `SourceBuffer.buffered` 只公开时间范围，没有标准方法把已经追加的数据取出。旁听后续 appendBuffer 可以复制未来缓冲，但需要提早安装并正确处理初始化段、编码切换和时间偏移，不能恢复安装前的数据；且增加对原播放器的干预，暂不作为首选。
- **独立解码**：使用合适的 MP4 解复用器读取初始化段和压缩音频样本，再通过 WebCodecs AudioDecoder 解码。不能把任意 m4s 网络块直接当作完整音频文件交给 decodeAudioData，也不能用隐藏播放器强行倍速播放替代离线解码。先验证本机对应音频编码的支持情况，内置解码器不可用时不自动下载执行代码。
- **滚动预取窗口**：先处理当前位置附近的小段，再逐渐积累目标 30–60 秒的字幕余量；这是建议初值，需实测资源和延迟后确定。一次推理、一个解码窗口，有界压缩和 PCM 内存；达到余量后等待。开始阶段或大幅跳转后仍可能需要准备时间，不自动暂停原视频。
- **时间定位**：字幕时间 = 解码后的片段媒体起点 + 模型段内时间；不能使用 HTTP 请求时间或推理结束时间。需处理 PTS、初始化段和 edit-list 等时间映射，连续采样和重叠段去重，仍只提供统一全局偏移。按视频身份/CID/音轨及任务代次拒绝旧结果，拖动后优先新位置，保留同源已生成时间轴。
- **吞吐边界**：如果模型处理 10 秒语音要花 15 秒，预取只能消耗提前积累的余量，不能长期保持实时。需记录真实音频时长、推理用时和字幕领先量；持续不足时告知用户或停止 AI，不能通过暂停视频掩盖性能不足。

下一实现验收：独立音轨可读和 Range 行为；生成字幕在其源时间到来前已存在；跳转/换 P 无串轨；长视频内存有界；采集和解码失败不干扰原播放。当前尚未实现音轨预取与提前解码，现有模型质量验证继续有效。

规范依据：[MSE SourceBuffer 接口](https://www.w3.org/TR/media-source-2/#sourcebuffer)、[WebCodecs AudioDecoder 与时间戳](https://www.w3.org/TR/webcodecs/#audio-decoder-interface)。
