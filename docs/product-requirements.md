# LayerPiP 产品需求与设计原则

> 产品意图于 2026-09-09 根据用户审查反馈更新；新增要求不代表当前代码已经实现或实机验收。架构分析与待核验项见 [文档与架构审查](./architecture-review.md)。

## 1. 原始问题

B站学习视频常出现完全相同的内容由不同 UP 主上传：早期投稿 A 有大量弹幕、没有官方字幕；后期投稿 B 弹幕少、却有官方字幕。用户希望继续观看 A，同时读取 B 的正确分P字幕，并在小窗播放时保留字幕和弹幕。

示例场景曾使用：A 为单P无字幕视频；B 为多P有字幕视频，A 对应 B 的 P57。这里最危险的失败不是“加载不到”，而是静默读取了错误分P并显示内容看似合理的错误字幕。

## 2. 目标用户与环境

- 单一主要用户，个人学习使用；优先可靠和便捷，不以商店发布或通用市场兼容为首要目标。
- 主要网站：`www.bilibili.com` 的视频页，兼顾现有 B站直播适配能力。
- 主要平台：macOS 上的 Microsoft Edge。
- 产品身份必须与旧的可用插件完全区分。旧插件是回退方案，不应被新项目覆盖、共用 ID 或共用存储。

## 3. 核心任务

### 3.1 字幕来源绑定

用户能为“当前 B站视频的当前分P”选择下列来源：

1. 自动：使用当前视频当前分P的第一条官方字幕；没有则安静地保持无字幕。
2. 当前视频官方字幕：固定某一语言轨道。
3. 另一个 B站视频：输入来源链接；链接含 `p` 时默认使用该分P，不含 `p` 时默认 P1；允许手动改选分P；保存后按 CID 绑定。
4. 网络字幕直链：HTTP(S) 的 SRT、ASS 或 B站字幕 JSON。
5. 本地字幕：SRT 或 ASS。
6. 关闭：对当前分P明确禁用字幕。

只支持全局时间偏移，不做分段校准：正数使来源字幕更早出现在目标视频上，负数使其更晚出现。首条有效字幕之前无当前字幕；最后一条结束后无当前字幕，但允许继续显示历史；视频先结束时不补播剩余字幕。偏移后无有效字幕时保持空状态，允许重新调整；seek 后重新计算。

观看页与字幕来源 URL 不带 `p` 均按 P1 解析。链接首次读取使用显式 P 或默认 P1，后续手动选择以用户选择为准。CID 绑定、分P目录变化和迟到结果分别由身份校验与生命周期处理，不改变 URL 默认值规则。

### 3.2 两种小窗模式

设置中由用户二选一，切换在下一次打开小窗时生效：

| 模式 | 产品定位 | 必须具备 |
| --- | --- | --- |
| 增强小窗 | 基于 Document Picture-in-Picture 的完整学习播放器 | 视频、弹幕、字幕、进度、音量、播放、设置、字幕历史、键盘控制、按 R 适配宽高比 |
| Edge 原生小窗 | 基于传统视频 PiP 的系统级轻量窗口 | 在同一 macOS Edge 环境及同一视频上，完整保留直接原生 PiP 已有的功能体验，再增加弹幕和字幕；不得以附加功能换取原生能力退化；具体样式设置放在插件设置内 |

两种模式共享字幕来源和主要视觉设置，但允许未来按模式分别存储字号等展示参数。当前源码仍使用共享字幕/弹幕字号配置，尚未实现每种模式独立配置。

### 3.3 多行历史字幕

底部最后一行/组是当前时刻字幕，其上显示最近若干段已结束字幕。用途不是做逐字稿，而是在用户按方向键跳过两三句话后，仍能快速知道刚刚跳过了什么。

设计约束：

- 快进、快退和任意 seek 后都由当前时间重新计算，不依赖“之前播放过”的事件缓存；
- 默认开启，默认 2 段，允许 1–5 段；
- 当前字幕优先，历史字幕弱化显示；
- 历史区最多占播放器高度约 35%，窗口太小时从最旧历史开始裁剪；
- 无字幕、时间轴空、当前时刻无字幕时不得导致小窗关闭或页面刷新；
- 增强小窗底栏有便捷开关，设置页也有开关与段数配置。

### 3.4 交互和视觉

- 以用户 2026-09-09 提供的 Bilibili 播放器截图为主要视觉参考：黑色内容区、紧凑底栏、细蓝色进度条、白灰图标、深色设置浮层和蓝色选中态。内容优先、控件按需显现；旧历史规范中的粉色选中态不再作为播放器控件依据。截图仅提供设计参考，不新增画质、编解码等无关功能，也不复制 B站官方标识。
- 使用独立名称、图标、强调色和固定扩展 ID，避免与旧插件混淆。
- 增强小窗不额外浪费常驻标题栏高度；浏览器不可控的系统栏不应被误写为可由 CSS 删除。
- 控制栏和顶部控件在鼠标/键盘交互时出现，闲置后隐藏；暂停状态不得依赖持续动画。
- 进度条常态细、命中区足够大；鼠标接近或拖动时加粗，圆点始终垂直居中；离开、释放指针、窗口失焦后必须恢复。
- 支持减少动态效果偏好，不使用容易触发 Document PiP 合成闪烁的持续毛玻璃或无意义动画。

### 3.5 快捷键与媒体控制

增强小窗的最低要求：

- Space：播放/暂停；
- ←/→：后退/前进 5 秒；
- Shift + ←/→：逐帧；
- ↑/↓：音量；
- M：静音；
- R：按视频宽高比自动调整小窗；
- S：字幕；D：弹幕；长按 →：临时倍速。

原生小窗不能依赖增强小窗的 DOM 键盘监听。它应通过原生 video 事件和页面 MAIN world 的 Media Session handler，把系统按钮与进度操作桥接回源视频。浏览器或操作系统不暴露的按钮不能由扩展凭空增加。

## 4. 可靠性不变量

1. **不串分P**：目标绑定以当前 CID 为边界；来源也以 CID 固定，P序号只用于首次选择和展示。
2. **单一源播放器**：播放状态、当前时间、音量和时长的权威来源始终是 B站原始 `HTMLVideoElement`。
3. **渲染可替换，状态不可分叉**：Document DOM 渲染与 Canvas 合成只是两种视图，不各自维护独立播放进度。
4. **一次会话一个 provider**：窗口关闭或基础打开失败后释放本会话资源，再次打开重新识别页面和配置；字幕和弹幕局部失败不关闭会话。
5. **迟到结果不可覆盖新页面**：字幕、弹幕等异步结果必须带生命周期代次或等价取消机制。
6. **空数据是正常状态**：无字幕、无弹幕、无音轨、直播、未登录或轨道消失必须显式降级或报错，不能崩溃。
7. **旧插件可回退**：不得修改、安装覆盖或复用旧插件身份。
8. **播放优先、附加功能隔离**：字幕/弹幕获取、解析、渲染或保存失败不得刷新页面、重开小窗、暂停或跳转源视频；停用失败功能并允许手动重试，不偷换字幕来源。
9. **恢复页面控制**：关闭后不得破坏页面原有及后来注册的媒体控制；清空扩展 handler 不等于恢复页面。原生模式显式 opt-in 不能替代完整能力验收。
10. **按关闭原因处理播放**：用户主动关闭可遵循其关闭暂停偏好；附加功能错误不进入关闭路径；小窗异常退出时优先保全/恢复源视频，不因统一清理策略额外暂停。

## 5. 非目标与边界

- 不承诺绕过 B站登录、权限、地区或 DRM 限制。
- 不承诺修改 Edge/macOS 原生 PiP 的系统标题栏、最大尺寸规则或未公开系统行为。
- 不把完整字幕正文同步到云端；本地大文件使用扩展本地数据库。
- 不以所有网站的所有 HTML5 视频为验收目标。Manifest 仍有宽泛 host 权限属于继承实现事实，应由审阅者判断是否收窄。
- 不以大型自动化测试套为交付目标；基础编译/静态检查由开发侧做，真实设备交互与长期稳定性由用户日常使用验证。

## 6. 产品级验收场景

1. A 无字幕、B 多P有字幕：输入含 `p=57` 的 B 链接，保存后 A 显示 B 的 P57 字幕。
2. B 链接不含 `p`：默认读取 P1，并明确展示当前分P；允许改选其他分P。P1 无字幕时仍保留目录，改选后须读取对应轨道再保存。
3. B 的 P序改变但原 CID 仍在：继续找到原内容；CID 消失则停止并要求重新绑定。
4. 当前分P无字幕：开启/关闭历史字幕不崩溃，小窗和网页不刷新。
5. seek 跨过多段字幕：当前字幕在底部，最近历史在上方，最旧内容先裁剪。
6. 增强小窗：Space、方向键、R、拖动进度条和自动隐藏在 Document PiP 内工作。
7. 原生小窗：系统播放/暂停、静音、seek 控件能同步源视频；合成画面持续显示视频、弹幕与字幕。
8. B站 SPA 切换视频/分P：旧异步结果不进入新视频；必要时关闭并提示重新打开。
9. 关闭或打开失败：原视频节点、标题、事件、定时器、Media Session handler 和 MediaStream 被恢复/释放；一项清理失败不阻断剩余清理，恢复时不得覆盖页面后来的有效状态。
10. 字幕/弹幕分别在加载和渲染时失败：基础视频持续播放，失败功能可单独重试，播放位置和暂停状态不被重试改变。
11. 对同一视频比较直接原生 PiP 与增强后原生 PiP 的实际控制、声音和窗口体验；任何原有能力退化都不算达标。
12. 字幕先结束时保留弱化历史；视频先结束不补播字幕；回退到字幕范围恢复正确当前/历史。
