保留单一源 video、CID 绑定、纯时间 SubtitleTimeline、DOM/Canvas 共享快照和显式 SiteAdapter 组合。没有依据进行全盘重写。最有价值的优化是明确基础播放、附加功能、页面身份和资源所有权之间的边界。

## 3. 最小职责调整建议（尚未实现）

### 3.1 基础播放与附加层

保留现有 provider 工厂与 SiteAdapter，不先拆目录或引入依赖注入框架。

- Provider 管理一次小窗会话、承载方式和本会话清理；基础视频应能在无字幕、无弹幕状态下建立。
- SiteAdapter 提供媒体身份、站点数据和节点变化通知，不决定窗口类型，不因可选数据失败终止会话。
- 字幕/弹幕各自拥有加载状态、错误、重试和释放。推荐状态为 idle/loading/ready/empty/error/disabled；empty 和 error 不混同。
- 渲染顺序仍是视频→弹幕→字幕，但失败隔离按层处理。Canvas 附加层绘制前后隔离绘图状态，避免字体、裁剪或透明度污染后续视频帧。
- 不重复逐帧抛错与提示：失败层停用，保留原因和手动重试入口；视频帧调度继续。重试须同时恢复数据及渲染依赖，不能只重复 fetch。

### 3.2 页面身份与异步结果

用现有 generation 机制补齐语义，不盲目增加更多计数器。

- 区分窗口会话失效、媒体身份变化、同一媒体内来源选择/重试；接受结果时核对对应归属。
- CID 改变但 video 对象未变，同样需要立即清空旧字幕/弹幕。
- video 对象改变但内容身份相同，也需要重新绑定事件和恢复责任，不能只比较 CID。
- 延迟回调必须同时考虑过期结果和自己刚创建的资源：不能只 return 而遗留晚到窗口或流。
- 设置保存复核目标，重试不改变绑定。无 p 的默认值与这些规则独立。

### 3.3 关闭与恢复

建议在现有关闭入口传递原因，不新增一套平行播放器状态机。

- 源 video 不属于扩展可销毁资源；扩展只撤销自己的移动、样式或控制干预。
- 独立资源逐项清理，一项抛错不跳过其余步骤；重复关闭幂等。
- 移动节点、改标题和注册处理器需记录所有权；关闭时不得把新页面恢复成旧页面状态。
- 换页时原父节点已被移除，不能机械插回失效父节点；优先保全当前站点播放器，具体策略留到代码核验。
- 原生节点替换时现有“关闭并提示重开”可作为保全播放的异常处理，但不能包装成与直接原生 PiP 同等连续体验的证明。

### 3.4 控制与 UI

先梳理现有命令入口，不为统一而重写已可靠的直接 video 控制。键盘、UI 和媒体桥最终作用于同一源 video；桥接须区分用户意图和镜像事件，拒绝/失败后仍能恢复正常控制。

UI 使用用户截图的蓝色交互与深色轻量控制层。视觉修改集中于样式和组件呈现，不重挂载源 video，不靠页面刷新应用配置。附加功能错误/重试放在相应设置区域；窄窗口优先保留播放、进度和核心学习控件，不照搬截图里的所有按钮。自动隐藏需尊重正在操作的设置、拖动和键盘焦点。

## 7. 2026-09-10 代码与架构续作

本节更新第6节的后续项，适用当前未提交候选；不改变产品需求。已实施：

- **基础合成独立持有。** CanvasPIPWebProvider 创建和释放合成器，弹幕引擎只借用。引擎初始化失败可以继续打开视频，卸载/重试不停止合成流。Canvas 按层捕获异常并保存/恢复绘图状态。

## 8. 保存、分P默认值与验收边界

本节为第7节后的当前续作状态。

- 修正字幕来源保存失败语义：新资产准备后、绑定前复核目标；写入结果不确定时回读，已提交资产保留，回读也失败则保留资产并提示重新检查。确认未引用的新资产才执行补偿清理；补偿失败明确提示。绑定成功后的旧资产清理失败不再显示成保存失败。该补偿机制不宣称跨数据库原子事务，进程中断及资产写入响应丢失仍可能留下未引用文件；不会为清理它们扫描或删除用户数据。
- 已保存本地字幕可以直接修改全局偏移，无需重新选择文件。
- 纠正文档阶段对用户无 p 要求的过度保留：观看页和来源链接均默认 P1；手动选择可覆盖 URL 默认值。P1 无字幕返回空轨道并保留目录。两个来源 UI 保留改选入口，未读取新分P的轨道前不能保存/导入旧轨道。
- 原生双向播放同步忽略与当前 paused 状态不一致的迟到事件，防止快速暂停/继续后旧 pause 反向暂停源视频。
- provider 的附加功能重试在每个 await 后核验本次恢复绑定是否仍有效；关窗或换页后不继续修改新会话的图层。
