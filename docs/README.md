## 1. 文档目的

这组文档供另一个 agent 独立审阅 LayerPiP。审阅者不需要依赖聊天记录，即可了解：

- 项目的原始问题、产品边界与两种小窗模式；
- 当前源码的模块划分、运行时数据流、存储与扩展身份；
- B站跨视频、跨分P字幕绑定如何防止抓错；
- 字幕历史、弹幕合成、键盘和原生媒体控制如何实现；
- 哪些内容已由源码静态确认，哪些仍待真实设备验证；
- 最值得对抗式检查的故障面和审阅问题。

## 2. 状态词的严格含义

| 状态 | 含义 |
| --- | --- |
| 已实现 | 当前源码中存在完整调用链；不代表真实设备已经验收 |
| 静态确认 | 已读取相关源码、配置或构建脚本并能追溯到具体符号 |
| 构建曾通过 | 历史工作记录称相应候选版本构建成功；本次文档工作没有重跑构建 |
| 用户已观察 | 用户在真实 macOS + Edge 环境中明确报告过的现象 |
| 候选修复 | 源码已针对报告修改，但修改后尚无用户确认 |
| 待实机验证 | 只能或最好由真实 Edge、系统画中画和双屏环境判断 |
| 已验收 | 只有用户明确确认可用时才使用；当前资料不把 `0.2.6` 整体标为已验收 |

## 5. 审阅范围

本次建议只做审阅，不直接假设可发布：

- 核对需求是否被架构完整覆盖；
- 找出实现和需求之间的缺口；
- 检查边界条件、竞态、资源释放、B站 SPA 导航和多分P身份；
- 检查 Document PiP 与原生 PiP 两套控制链是否各自闭环；
- 判断哪些继承代码值得继续保留，哪些兼容分支增加了无收益风险；
- 输出按严重度排序的结论，并区分“源码确定问题”和“需要实机复现的问题”。

本次文档落盘没有修改功能代码、安装扩展、生成发布包、提交或推送 Git。
